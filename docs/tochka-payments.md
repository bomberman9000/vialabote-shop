# Онлайн-оплата через Точку (платёжные ссылки)

## Как работает

1. Покупатель оформляет заказ → `POST /api/orders` в одной транзакции создаёт заказ `AWAITING_PAYMENT`
   и резервирует товар (`reserveForOrder`, журнал `StockChangeLog`). Нет остатка — 409, заказ не создаётся.
2. Банк создаёт платёжную ссылку (`POST /acquiring/v1.0/payments`, карта + СБП).
3. Покупатель попадает на `/checkout/pay/<номер>`: сумма, таймер 10:00 и кнопка «Оплатить».
   Страница каждые 4 с спрашивает `GET /api/orders/<номер>/payment`, тот сверяет заказ с API банка.
4. Банк подтвердил `APPROVED` с той же суммой → `PAID` + `WRITE_OFF`. Корзина очищается.
5. 10 минут прошли без оплаты → `CANCELLED` + `RELEASE` (товар вернулся в продажу), ссылка больше не выдаётся,
   корзина сохранена. Просроченные заказы отменяются и без открытой вкладки: «подметальщик» запускается
   из маршрутов статуса и вебхука (не чаще раза в минуту).
6. Вебхук банка `acquiringInternetPayment` → `POST /api/payment/tochka/webhook`: подпись JWT (RS256, ключ
   `https://enter.tochka.com/doc/openapi/static/keys/public`) проверяется, затем статус берётся из API банка.

Статус оплаты никогда не берётся из браузера или тела вебхука. Переходы статуса — условный `updateMany` в той же
транзакции, что и движение склада. Оплата, пришедшая после отмены по таймеру, помечается `PAID` с комментарием
«проверьте наличие» (резерв к этому моменту уже снят).

Старый вебхук ЮKassa `/api/payment/webhook` отвечает 404, пока ЮKassa не настроена: он доверяет телу запроса.

## Переменные окружения (`/etc/vialabote-shop/app.env`)

| Имя | Обязательно | Что это |
|---|---|---|
| `TOCHKA_API_TOKEN` | да | JWT-ключ из «Интеграции и API» (секрет) |
| `TOCHKA_CUSTOMER_CODE` | да | код компании с правами эквайринга: `303256308` (из Get All Consents → child; не `customer_code` из JWT) |
| `TOCHKA_MERCHANT_ID` | нет | `200000000047121`; нужен только при нескольких торговых точках |
| `TOCHKA_CLIENT_ID` | для вебхука | `client_id` JWT-ключа, только для регистрации вебхука |
| `TOCHKA_API_BASE` | нет | по умолчанию `https://enter.tochka.com/uapi` |

Без `TOCHKA_API_TOKEN` или `TOCHKA_CUSTOMER_CODE` магазин работает как раньше (заказ `NEW`, оплата при получении).

## TLS

API и ключ банка подписаны НУЦ Минцифры. Процессу магазина нужен корень «Russian Trusted Root CA»
(SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`)
только через `NODE_EXTRA_CA_CERTS` в `vialabote-shop.service` — системное хранилище не трогаем.

## Вебхук

Регистрация один раз (`PUT /webhook/v1.0/{client_id}`, `webhooksList: ["acquiringInternetPayment"]`,
`url: https://shop.vialabote.ru/api/payment/tochka/webhook`). Только HTTPS на 443. Банк сразу шлёт тестовый вебхук —
маршрут должен ответить 200.
